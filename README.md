# ゲームの概要・ルール
## コンセプト
設計思想をアピール出来る題材として、タワーディフェンスゲームを採用しました。
## 概要
拠点に敵が到着する前にタワーを設置して迎撃するゲームになります。  
拠点のHPが無くなればゲームオーバー、敵を全員迎撃し切ればゲームクリアになります。 
## 操作方法
マウス操作で遊びます。
1. 配置したいタワーの種類を左下のボタンから選び、ボタンを押下します。
2. 配置したい森（緑のマス目）を選び、マウスをクリックします。道（黄色のマス）や拠点は配置ができません。
3. 右上の所持GOLDが足りるまでは配置が可能です。
4. 右下のボタンを押下することで、ゲームが開始され敵が出現します。
5. 設置したタワーが弾を発射することで敵にダメージが加算され敵のHPが無くなり次第消滅します。
6. 左上の現在WAVE数が5回目に到達し、出てくる敵を全て消滅させることでゲームクリアとなります。
7. 全ての敵を消滅させるよりも先に真上の拠点HPが0になるとゲームオーバーとなります。
# こだわった点・技術的アピール
## オブジェクト指向設計を意識
前職ではiOSアプリをSwiftで実装していましたので、作り方や考え方など異なる部分も多く    
Unityの知識が足りないながらも調べながら意識して実装いたしました。  
## シーンを挟むシングルトンとシーンを挟まないシングルトンの実装
シーンを挟むシングルトンは、どのシーンを起動しても音楽を再生できるように  
シーンを挟まないシングルトンは、オブジェクトの一括管理のために実装いたしました。  
## マスターデータをScriptableObjectで管理
コード上でマスター情報を管理するよりコード外で管理する方が  
エンジニアではない人でも触りやすいと考え、実装いたしました。  
又、フィールド情報のみ数字の羅列よりも直感的に編集ができた方が誰もが扱いやすいと考え  
エディターの実装も行いました。  
## Actionを発火する関係
振る舞いを極力依存しない形にすることで役割が明確になるため実装いたしました。  
## 弾をタワーと敵に依存しない形で実装
今回実装した処理の中で敵が攻撃をする振る舞いは実装されておりませんが  
将来的に敵から攻撃をさせたい場合にタワーに依存しているとその分処理が増えてしまうため  
インターフェースで必要な振る舞いを実装することでどのオブジェクトから攻撃をしようと  
ダメージが入るよう実装いたしました。

# 今後の課題・実装予定の機能
## レベルデザインが出来ていない
現状はゲームシステムの実装を優先しており  
敵の出現構成や難易度調整などの全体的なレベルデザインが未調整なので  
今後はプレイテストを通じてゲームバランスを調整していきます。
## ゲームの独自性
ゲーム性やビジュアル表現がありきたりなものに留まっているため  
独自性のあるゲーム体験を提供できるよう改善していきます。
## ステージの追加
現在はステージ数が限られているため、繰り返し遊べるゲームとして  
異なるマップや敵の出現構成のステージを追加していきます。
## フィールドの固定幅の撤廃
現在はフィールドの幅が固定されているため  
任意の幅を設定できるように改修し、異なる幅のフィールドにも対応していきます。
## コードの改善
今回実装したコードを見直し、より良い実装方法がないか継続的に検討していきます。
## Git運用の改善
現在は個人開発を前提としたコミット管理を行なっているため  
第三者が変更内容や実装意図を理解しやすいように  
コミットメッセージの記述方法やコミットの粒度を見直していきます。
